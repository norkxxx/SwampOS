# Build 14 — Resumable native GUI

The existing fixed `/bin/gui-demo` ELF now publishes 24 frames via syscall 11, then yields with syscall 5 after each frame. Its user address space and saved GPR/IRET frame survive between calls. A trusted `user_resume` assembly entry saves the desktop's kernel callee-saved registers, restores the saved user registers and enters Ring 3 via IRETQ. Timer interrupts (two PIT ticks) and voluntary yield copy the trap frame and escape to the saved kernel stack. CR3 is restored before desktop rendering, output copy or page destruction. The first entry uses the same fixed user CS/SS and RFLAGS profile as the existing runtime.

In windowed Paint, Shift+G starts a single client; Shift+X or closing Paint cancels it. Desktop polls at five PIT ticks and presents validated 16x8 palette frames on the existing Paint canvas. The client can consume at most 100 slices. The old synchronous `gui-demo` command still commits only the final image on clean exit. `gui-async-test` expects exactly 24 publications and a clean exit from the resumable path; included in USB and optical guest test scripts.

Only CAP_GUI is granted, never console, IPC, resource access, scratch or device privileges. Frame publication uses the existing readable-pointer check and palette validation. No raw framebuffer mapping is exposed to user mode. Fault or nonzero exit discards the current staged frame. Cancellation frees VM pages and clears registers and staged pixels; previously displayed pixels are not erased from Paint. Other native launches are rejected while the GUI job is live. Before each slice, storage checks the inode ceiling and captured policy/mount revision. Any policy change or remount cancels conservatively, including unrelated changes. There is no live revocation for the other synchronous processes.

Limitations: single fixed bundled client, no general GUI event IPC, no parallel native process group, no input delivery to the native client, no floating-point/SIMD context, no SMP. Host tests use the real dispatcher but mock CPU entry and CR3. The actual assembly IRETQ path requires guest testing. No physical disk or USB behavior changed.

Run `make gui-async-host-test guard-host-test`, then `make live-runtime` and `make live-optical-runtime` when QEMU/OVMF are installed. Manual guest: boot the first Live option, type `gui-async-test` in Terminal; expect `GUI_ASYNC_TEST_OK`. Open Paint and press Shift+G, switch focus, and verify animation plus cancellation with Shift+X or window close. Repeat after `guard-set /bin/gui-demo 0` (must deny) and `guard-set /bin/gui-demo 32` (allows explicit launch).
