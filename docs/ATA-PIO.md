# Read-only ATA PIO — Build 09

`drivers/storage/ata/pio.c` separates the ATA command engine from the x86 port adapter in `kernel/ata.c`. The existing secondary legacy IDE master (0x170/0x376) remains the only kernel-connected target. IDENTIFY validates LBA capability, command-set validity and 512-byte logical sectors. It rejects ATAPI, invalid capacities and unsupported long logical sectors. Reads use LBA28 below 2^28 sectors and LBA48 above that boundary when advertised. The LBA48 command writes the high-order task-file bytes before low-order bytes. Transfers are one sector per command, polling only, up to 128 sectors per block API call; failure can leave partial data in the caller buffer and must be treated as a failed read. No write-sector commands, DMA or controller reset are implemented. The current backend is serialized, single CPU and is not suitable for hotplug or concurrent I/O.

`ata-info` is available only in the non-Live IDE lab. The Live shell and hardware adapter reject physical ATA access, preserving the embedded read-only EXT4 RAM disk. Do not attach real writable host disks to experimental VMs. The larger addressing range does not imply full GPT/EXT4 support for large files or drives.

`make ata-host-test` executes the actual driver against mock port I/O with UBSan. Tests cover boundary crossing, high/low register ordering, sector contents, invalid capacities, sector size, absent/busy/packet/error states, and 50,000 deterministic IDENTIFY mutations. Mock tests do not establish controller interoperability. Guest, AHCI, NVMe and USB transport remain pending.
