# SwampGuard audit foundation

The kernel maintains a bounded 64-event in-memory ring with monotonic sequence numbers (saturates at UINT64_MAX). Events are emitted for rejected syscalls (kind 1: result errno, detail syscall number), watchdog (kind 2), user fault (kind 3: detail vector), and completed user run (kind 4: detail granted console bit). No raw user buffers, passwords or memory contents are logged. `audit` prints retained events oldest first; `audit-test` runs the deterministic self-test. A boot marker gates BOOT_OK. Host tests exercise wraparound and ordering. The ring overwrites old events and is lost on reboot. This single-core prototype is not a tamper-resistant or persistent audit trail, has no app identity or policy management UI, and cannot prove user isolation until guest tests run.
