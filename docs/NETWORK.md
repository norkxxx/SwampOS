# Network foundation | Offline frame engine

`kernel/net.c` implements a bounded stateless Ethernet-II frame processor for one configured MAC/IPv4 endpoint. It constructs ARP replies, ICMP echo replies and checksummed UDP port-7 echo replies into a separate caller-provided output buffer. It rejects nonlocal destinations, invalid source MACs, invalid lengths/checksums, IP fragments/options and unsupported protocols. UDP zero checksums are deliberately rejected by this narrow profile. `net` prints the scope; `nettest` runs three positive and three negative fixtures using documentation-only IP addresses (192.0.2.0/24). The engine is not attached to any NIC, does not transmit on a wire, has no routing, ARP cache, DHCP, DNS, IPv6, TCP, sockets or per-app network grants. Guest commands launch without an attached network adapter. This is a protocol foundation, not a system VPN or firewall. Future NIC DMA requires device isolation; network access remains default-deny for all applications.

## 0.9.0 Connectivity update (supersedes the offline-only scope above)

The original frame engine is retained. The explicit `netlab` kernel-console command can initialize one legacy transitional VirtIO PCI network device (vendor/device 1af4:1000), with only the MAC feature, split RX/TX rings, no offloads, no mergeable RX, polling, static low-memory DMA buffers and a finite polling window (up to 1000 PIT ticks or an iteration limit). It rejects an already bus-mastering device and requires a recognized TCG/KVM CPUID signature, which is not a security attestation. It resets the device and disables PCI bus mastering on exit. A failed reset prevents subsequent sessions until reboot. No physical hardware testing; without IOMMU the device is trusted. Normal QEMU targets still use `-nic none`. `make network-lab-runtime` attaches a local loopback socket peer only, exercises ARP and ICMP, and records the real guest serial log if available. No NAT, bridge, forwarding, real Internet or Ring 3 network syscalls. The driver is built, not runtime verified.

`transport.c` validates TCP over fixed IPv4 headers and checksums, bounded TCP options, compressed DNS message structure (not resolver semantics), DHCP response TLVs (not leases), and basic IPv6 fixed header/length only (no extension headers or transport checksum). These parsers do not handle live TCP/IPv6/DNS/DHCP traffic. `swampwall.c` implements a bounded exact IPv4 endpoint grant table keyed by app ID, protocol and destination port; revoke removes all grants for that app. There is no socket enforcement. `vpn_policy.c` models drop/tunnel/direct decisions, including no fallback when a tunnel is required, and a global kill switch blocking direct routes. No actual VPN backend, route, DNS or IPv6 leak prevention exists. `tools/vpn_inspect.py` handles a constrained local URI metadata subset; never connects or logs userinfo/query/fragment. No source discovery, subscriptions, VMess/JSON/YAML or tunnel configuration validation. Normal applications have no networking syscall; no claims of a complete firewall or VPN.
